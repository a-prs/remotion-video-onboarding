# remotion-video-onboarding — от пустой машины до первого смонтированного видео

Ты ведёшь диалог, а не выполняешь разовую команду. Пользователь может быть человеком, который
никогда не открывал терминал — веди его по шагам ниже **по порядку**, объясняя коротко, что и
зачем происходит, не грузя техническими деталями сверх необходимого. Если пользователь явно
говорит «просто ставь всё и не спрашивай» — можно ускориться, но шаги 2 (риск для системы), 4
(цвета И шрифт — оба, не только цвета) и 6 (обязательное предложение графики) всё равно нельзя
пропускать молча, см. почему в этих шагах.

## Шаг 0. Определи платформу и агента

Одно и то же — на Claude Code (терминал), Claude Desktop (вкладка **Code**, не Chat и не
Cowork — в тех проектные скиллы не видны) и на Codex. Если это Codex — сразу читай
`references/codex.md`, там свой путь установки скилла (формат `SKILL.md` тот же, но раскладка
другая) и важное ограничение: у Codex нет браузерной панели превью, рендер придётся смотреть
через `localhost` в обычном браузере пользователя, а не внутри агента.

**Если это Claude Desktop, но у тебя нет доступа к файловой системе/терминалу** — это значит,
что сообщение отправили во вкладку Chat или Cowork, а не Code (в Chat нет доступа к файлам
вообще, пользователь мог просто вставить этот промпт текстом не в ту вкладку). Не пытайся
выполнять шаги ниже. Скажи прямо первым же сообщением: «этот скилл работает с файлами на диске
— переключись на вкладку **Code** (сверху по центру окна Desktop), там выбери Local → Select
folder и укажи (или создай новую) пустую папку под проект, и уже там пришли это же сообщение
снова». Продолжай только после того, как убедился, что находишься в Code (виден доступ к
файлам/bash).

## Шаг 1. Проверь окружение, поставь то, что безопасно ставить без вопросов

Всё через `npx` (Node-пакеты, никакого sudo, ставится в пределах пользовательской папки) —
ставь сразу, не спрашивая лишний раз:
- Node.js 18+ — если его нет вообще, это единственное, что нужно от пользователя поставить
  руками (обычный инсталлятор с nodejs.org) — ты не можешь поставить сам интерпретатор.
- Проект Remotion: `npx create-video@latest --yes --blank my-video && cd my-video && npm install`
  — если текущая папка уже внутри git-репозитория, эта команда упадёт: создай `my-video` в
  отдельной пустой папке вне git.
- Официальный набор скиллов: `npx skills add remotion-dev/skills --skill '*' --agent claude-code -y`
  (флаги обязательны — без них команда интерактивная и без TTY зависнет). Ставится в
  `./.claude/skills/` внутри проекта — если сессия уже была открыта в этой папке, перезапусти её.
- FFmpeg/ffprobe — сами скачаются при первом реальном вызове `npx remotion ffmpeg/ffprobe`,
  прогревать заранее не нужно (в отличие от браузера ниже, отдельной команды прогрева для них нет).
- Headless-браузер для рендера: `npx remotion browser ensure` — прогрей сразу, иначе первый
  реальный рендер скачает ~150 МБ Chrome Headless Shell и может упасть 403 за корпоративным
  прокси/в закрытом контуре (тогда — `--browser-executable=<путь к своему Chrome>`).
- Whisper для субтитров: `npx remotion add @remotion/install-whisper-cpp` (не `npm install` —
  версия должна остаться в связке с остальными `@remotion/*`-пакетами, иначе может разъехаться).

Полный список под конкретную ОС (apt-либы для Linux headless-браузера, платформенные нюансы) —
`references/os-install.md`. Прочитай его прежде чем ставить что-то на Linux.

## Шаг 2. Спроси разрешение отдельно на всё, что трогает систему целиком

Если понадобится `apt install` (Linux, системные библиотеки для headless-браузера) —
**спроси в диалоге явно**, не полагайся только на то, что харнесс и так спросит подтверждение
команды. Пользователь может быть в режиме автоодобрения команд и не осознавать, что скилл про
монтаж видео сейчас полезет ставить системные пакеты на его машину. Одна фраза достаточно:
«для рендера видео на Linux нужно поставить N системных библиотек через apt — ставлю?» — и жди
ответа, прежде чем выполнять.

Если что-то из установки упало на середине (сеть, нет прав) — не начинай с нуля: `detect_env`
логика должна сама увидеть, что уже стоит, и продолжить только с недостающего. Скажи
пользователю, что конкретно не встало и что сделать руками, если автоустановка не может.

## Шаг 3. Объясни официальный набор скиллов — ты дирижёр над ним, не замена

Официальный `remotion-dev/skills` — это 12 скиллов, и пользователю не нужно самому лезть в
документацию Remotion, чтобы понять, какой когда нужен. Коротко объясни (не грузи все 12 сразу
списком — упомяни по ходу дела, когда реально понадобится):

- `/remotion-create` — новый проект/композиция.
- `/remotion-markup` — разметка сцены: анимации, типографика, медиа.
- `/remotion-render` — рендер в видео/стилл.
- `/remotion-captions` — субтитры (сам транскрипт не делает без whisper-cpp, см. Шаг 1).
- `/remotion-studio` — локальный превью-сервер.
- `/remotion-best-practices` — используй как общий ориентир, если не уверен, какой из
  остальных скиллов нужен именно сейчас.
- `/remotion-docs`, `/remotion-upgrade`, `/remotion-maps`, `/remotion-saas`,
  `/remotion-interactivity`, `/remotion-multimedia` — служебные, включай по ходу задачи, если
  она реально их касается (карты, апгрейд версии, интерактив и т.д.) — не обязательны для
  обычного монтажа одного ролика.

## Шаг 4. Стайлкит + мини-экскурс возможностей — спроси стиль И шрифты, НЕ дефолти в клише

**Этот шаг нельзя пропускать молча** (как шаги 2 и 6, см. вступление выше) — даже если
пользователь сказал «ставь всё и не спрашивай», цвета и шрифты спроси явно одной короткой фразой,
не дефолти в тишине.

Спроси: «какие цвета хочешь для графики в видео? Если нет идеи — пришли 1-2 референсные картинки
(скриншот бренд-гайда, любимый сайт, любая картинка с нужным настроением), я вытащу оттуда
палитру». Если пользователь прислал картинки — посмотри на них (у тебя есть зрение, отдельный
инструмент не нужен) и вытащи 2-3 реальных hex-цвета, которые в них доминируют.

**Отдельно спроси про шрифт** — это легко забыть, если вопрос про цвета и шрифты слить в одну
фразу вскользь, поэтому задавай его явно: «какой шрифт хочешь для заголовков/подписей? Можно
название реального Google Font, можно «на твой вкус»». Если ответа нет или пользователь не
против дефолта — **Montserrat (текущий дефолт) это нормально оставить**, но сам вопрос задать
обязательно, не просто молча оставить дефолт.

Если пользователь совсем без мнения и без референсов на цвет — **не дефолти в фиолетовый
градиент**, это самый узнаваемый штамп «сгенерировано ИИ». Дефолт — тёмно-графитовый фон
(`#16181d`) + один спокойный акцент (терракот `#c9704f` или тёмная бирюза `#2f7a78`), плоские
заливки, без градиентов и свечения вообще.

Возьми `assets/stylekit.ts` как шаблон (там уже расписано, какие поля обязательны — их читают
все компоненты банка примитивов) и перезапиши `colors` под то, что выяснил — это простая замена
значений, форму объекта не трогай.

**Шрифт — это НЕ простая замена значения**, в отличие от цветов: `style.fonts.heading` и т.д.
получаются из `loadFont()` конкретного пакета `@remotion/google-fonts/<Name>` (см. импорты вверху
`stylekit.ts`), а не пишутся строкой напрямую. Чтобы реально сменить шрифт под ответ пользователя:
1. Найди нужный шрифт в каталоге `@remotion/google-fonts` (пакет называется по имени шрифта,
   например `@remotion/google-fonts/Inter`) — если пользователь назвал шрифт не из Google Fonts
   или которого там нет, честно скажи и предложи ближайший похожий.
2. Проверь поддержку кириллицы (`subsets`) у выбранного шрифта, если ролик на русском — не у
   каждого Google Font она есть. Если нет — предупреди пользователя и оставь Montserrat для
   кириллического текста (он кириллицу поддерживает гарантированно), можно применить новый шрифт
   только к латинским элементам (как уже сделано с `PIXEL`/Silkscreen в файле).
3. Замени `import { loadFont as loadSans } from "@remotion/google-fonts/Montserrat"` на нужный
   пакет, оставь структуру `loadFont(...)` и имена экспортов (`SANS`/`style.fonts.heading` и т.д.)
   как есть — меняется только ЧТО загружается, не форма объекта `style`.

## Мини-экскурс: что вообще можно попросить

Прежде чем переходить к видео — коротко объясни пользователю, что тут вообще можно строить, а не
жди, пока он сам догадается спросить (он может не знать, что возможно в принципе):
- **Готовые интерфейсы/карточки/графики** — из банка (`references/primitive-map.md`): терминал,
  переписка с ИИ, счётчики/графики/диаграммы, зачёркивания и вердикты, цитаты и т.д.
- **Кастомная графика с нуля** — если в банке нет нужного (браузерное окно, телефонный мессенджер,
  дашборд — таких заготовок сейчас нет), можно нарисовать новый компонент под конкретный запрос:
  «опиши, как ты это видишь, или пришли референс (скриншот/схема) — попробую отрисовать».
- **Целая сцена**, а не один элемент — можно попросить собрать составную сцену из нескольких
  примитивов вместе (не только один блок за раз).
- **Динамический фон** из цветных пятен/градиента — это НЕ готовый компонент в банке сейчас,
  но Remotion умеет такое рисовать с нуля так же, как и остальную графику.
- **Куда садится графика** — три варианта, спроси, что нужно: оверлеем поверх видео (лицо видно),
  отдельным сегментом ролика (видео на паузе/скрыто на это время), или вместо видео целиком
  (заменяет кадр, а не дополняет).

## Шаг 5. Первое видео — спроси, где лежит, предупреди о времени/расходе

Спроси, куда положить исходник (или можно перетащить файл прямо в чат). Перед тем как запускать
тяжёлую обработку — проверь длительность (`ffprobe`) и, если файл длинный (по ощущению — от
30-40 минут), явно предупреди: «файл на N минут, обработка (транскрипция+рендер) займёт примерно
столько-то и заметно потратит дневной лимит — продолжаем или сначала возьмём кусок покороче для
теста?». Не запускай тяжёлый пайплайн молча на файле любого размера.

## Шаг 6. Обработка — по порядку, ничего не пропускать

1. **Транскрипция** через `@remotion/install-whisper-cpp` с `tokenLevelTimestamps: true` и
   флагом `--dtw` — без них не будет word-level тайм-кодов, а они нужны на следующем шаге.
2. **Вырезание пауз** — `scripts/cut_silence.py <video> <words.json> <out.mp4> <out_words.json>
   --audio --gap 0.8 --pad 0.15 --level` (флаг `--audio` обязателен — режим по умолчанию в
   скрипте баговый, режет живую речь, см. докстринг скрипта; **`--gap 0.8 --pad 0.15` тоже
   обязательны** — без них берётся дефолт скрипта `--gap 0.35`, который для разговорной речи
   режет слишком агрессивно и на выходе рвёт естественные паузы/дыхание — ровно так выглядит
   жалоба «паузы вырезаны некачественно»; `--level` сразу прогоняет выравнивание голоса тем же
   заходом). Подробнее, почему именно так — `references/audio-pipeline.md`.
3. **Субтитры** — используй `assets/primitives/SubtitleTrack.tsx` (`<SubtitleTrack words={cutWords} />`
   как оверлей поверх композиции, значения бери из `cut_words.json` шага 2 — слова там уже
   примагничены к новому таймлайну, ни одно не потеряется на вырезанных паузах). Это наш
   выверенный karaoke-компонент (группировка по 3 слова/паузе >0.7с/2.8с максимум на экране,
   активное слово подсвечено плашкой) — НЕ используй дефолтную стилистику официального
   `/remotion-captions` для самого рендера субтитров, она даёт рубленые, слишком короткие
   фрагменты без нашей группировки. `/remotion-captions` можно звать только чтобы ПОЛУЧИТЬ
   субтитровый файл/структуру данных, если она вдруг понадобится отдельно — не для финального
   визуала.
4. **Улучшение голоса** — если не сделал флагом `--level` на шаге 2, отдельно
   `scripts/clean_audio.py <video> --render <out>`. Диагностирует и чинит только то, что реально
   сломано (шум/громкость/клиппинг) — не гарантированно «улучшает» звук вслепую, это осознанно.
5. **Обязательный шаг — предложи графику, не жди вопроса.** Прогони расшифровку через словарь
   «маркер речи → примитив» (`references/marker-action-library.md`, реализация примитивов —
   `references/primitive-map.md`, сами компоненты — `assets/primitives/`) и **сформулируй
   конкретно 1-3 места с конкретной графикой** («на 0:14, где ты говоришь про рост в 3 раза —
   предлагаю countUpNumber») — этот шаг нельзя молча пропустить и нельзя заменить общим
   «нужна ли графика?». Дай пользователю решить, какие вставки брать.
6. **Рендер.**

## Правило: новый примитив ИЛИ целая сцена — всегда предлагай занести в банк насовсем

Если по ходу работы (не только на первом видео — в любой сессии) пользователь попросил что-то,
чего нет в `assets/primitives/`, и ты нарисовал компонент с нуля под его конкретный запрос —
**ИЛИ собрал вместе с ним целую сцену** (составную композицию из нескольких примитивов/переходов,
не сводится к одному файлу) — **всегда спроси, сохранить ли это насовсем**, а не только для
этого ролика. Не жди, что пользователь сам догадается попросить — задай вопрос прямо
(«получилось неплохо — сохранить как постоянный [примитив в банке / пример сцены], чтобы
предлагать его и в следующих видео?»).

- Если это ОДИН компонент — положи файл в `assets/primitives/`, добавь запись в
  `references/primitive-map.md` (props, когда уместен) и, если подходит под существующую семью —
  в `references/marker-action-library.md`.
- Если это ЦЕЛАЯ СЦЕНА (несколько примитивов вместе) — сохрани композицию как отдельный пример в
  `assets/scenes/<короткое-имя>.tsx` (папки может не быть — создай), с комментарием сверху, из
  чего она собрана и когда уместна. Отдельного реестра под сцены пока нет — этого формата
  достаточно, дальше решим по мере накопления примеров.

Банк растёт от реального использования, не только от того, что заложено при сборке скилла —
**подскажи сам, что так можно, а не жди, пока пользователь захочет что-то нестандартное.** Когда
уместно (например, на Шаге 4 про стиль/экскурс возможностей, или если видно, что ни один примитив
банка не подходит под задачу) — намекни: «если есть скриншот или схема с графикой, которая
нравится (референс, не обязательно из видео) — пришли, я попробую отрисовать похожий примитив,
доведём его до ума и сохраним в банк как обычный». Не только цвета/шрифты тянутся из референсов —
новый примитив тоже можно собрать с картинки, не только по словесному описанию.

## Шаг 7. Превью

- **Claude Desktop (вкладка Code)**: запусти `npx remotion studio`, dev-сервер откроется прямо
  в Browser-панели приложения — ничего дополнительно открывать не надо.
- **Claude Code в терминале**: `npx remotion studio`, дай пользователю открыть выведенный адрес
  в браузере самому.
- **Codex**: своего превью-окна нет — тот же `npx remotion studio`, но адрес нужно открыть в
  обычном браузере пользователя руками, агент это увидеть не может.
