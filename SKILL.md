# remotion-video-onboarding — от пустой машины до первого смонтированного видео

Ты ведёшь диалог, а не выполняешь разовую команду. Пользователь может быть человеком, который
никогда не открывал терминал — веди его по шагам ниже **по порядку**, объясняя коротко, что и
зачем происходит, не грузя техническими деталями сверх необходимого. Если пользователь явно
говорит «просто ставь всё и не спрашивай» — можно ускориться, но шаги 2 (риск для системы) и 6
(обязательное предложение графики) всё равно нельзя пропускать молча, см. почему в этих шагах.

## Шаг 0. Определи платформу и агента

Одно и то же — на Claude Code (терминал), Claude Desktop (вкладка **Code**, не Chat и не
Cowork — в тех проектные скиллы не видны) и на Codex. Если это Codex — сразу читай
`references/codex.md`, там свой путь установки скилла (формат `SKILL.md` тот же, но раскладка
другая) и важное ограничение: у Codex нет браузерной панели превью, рендер придётся смотреть
через `localhost` в обычном браузере пользователя, а не внутри агента.

## Шаг 1. Проверь окружение, поставь то, что безопасно ставить без вопросов

Всё через `npx` (Node-пакеты, никакого sudo, ставится в пределах пользовательской папки) —
ставь сразу, не спрашивая лишний раз:
- Node.js 18+ — если его нет вообще, это единственное, что нужно от пользователя поставить
  руками (обычный инсталлятор с nodejs.org) — ты не можешь поставить сам интерпретатор.
- Проект Remotion: `npx create-video@latest --yes --blank my-video && cd my-video && npm install`
  — если текущая папка уже внутри git-репозитория, эта команда упадёт: создай `my-video` в
  отдельной пустой папке вне git.
- Официальный набор скиллов: `npx skills add remotion-dev/skills --skill '*' --agent claude-code -y`
  (флаги обязательны — без них команда интерактивная и без TTY зависнет). Ставится в
  `./.claude/skills/` внутри проекта — если сессия уже была открыта в этой папке, перезапусти её.
- FFmpeg/ffprobe — сами скачаются при первом реальном вызове `npx remotion ffmpeg/ffprobe`,
  прогревать заранее не нужно (в отличие от браузера ниже, отдельной команды прогрева для них нет).
- Headless-браузер для рендера: `npx remotion browser ensure` — прогрей сразу, иначе первый
  реальный рендер скачает ~150 МБ Chrome Headless Shell и может упасть 403 за корпоративным
  прокси/в закрытом контуре (тогда — `--browser-executable=<путь к своему Chrome>`).
- Whisper для субтитров: `npx remotion add @remotion/install-whisper-cpp` (не `npm install` —
  версия должна остаться в связке с остальными `@remotion/*`-пакетами, иначе может разъехаться).

Полный список под конкретную ОС (apt-либы для Linux headless-браузера, платформенные нюансы) —
`references/os-install.md`. Прочитай его прежде чем ставить что-то на Linux.

## Шаг 2. Спроси разрешение отдельно на всё, что трогает систему целиком

Если понадобится `apt install` (Linux, системные библиотеки для headless-браузера) —
**спроси в диалоге явно**, не полагайся только на то, что харнесс и так спросит подтверждение
команды. Пользователь может быть в режиме автоодобрения команд и не осознавать, что скилл про
монтаж видео сейчас полезет ставить системные пакеты на его машину. Одна фраза достаточно:
«для рендера видео на Linux нужно поставить N системных библиотек через apt — ставлю?» — и жди
ответа, прежде чем выполнять.

Если что-то из установки упало на середине (сеть, нет прав) — не начинай с нуля: `detect_env`
логика должна сама увидеть, что уже стоит, и продолжить только с недостающего. Скажи
пользователю, что конкретно не встало и что сделать руками, если автоустановка не может.

## Шаг 3. Объясни официальный набор скиллов — ты дирижёр над ним, не замена

Официальный `remotion-dev/skills` — это 12 скиллов, и пользователю не нужно самому лезть в
документацию Remotion, чтобы понять, какой когда нужен. Коротко объясни (не грузи все 12 сразу
списком — упомяни по ходу дела, когда реально понадобится):

- `/remotion-create` — новый проект/композиция.
- `/remotion-markup` — разметка сцены: анимации, типографика, медиа.
- `/remotion-render` — рендер в видео/стилл.
- `/remotion-captions` — субтитры (сам транскрипт не делает без whisper-cpp, см. Шаг 1).
- `/remotion-studio` — локальный превью-сервер.
- `/remotion-best-practices` — используй как общий ориентир, если не уверен, какой из
  остальных скиллов нужен именно сейчас.
- `/remotion-docs`, `/remotion-upgrade`, `/remotion-maps`, `/remotion-saas`,
  `/remotion-interactivity`, `/remotion-multimedia` — служебные, включай по ходу задачи, если
  она реально их касается (карты, апгрейд версии, интерактив и т.д.) — не обязательны для
  обычного монтажа одного ролика.

## Шаг 4. Стайлкит — спроси стиль, НЕ дефолти в клише

Спроси: «какие цвета/шрифты хочешь для графики в видео? Если нет идеи — пришли 1-2 референсные
картинки (скриншот бренд-гайда, любимый сайт, любая картинка с нужным настроением), я вытащу
оттуда палитру». Если пользователь прислал картинки — посмотри на них (у тебя есть зрение,
отдельный инструмент не нужен) и вытащи 2-3 реальных hex-цвета, которые в них доминируют.

Если пользователь совсем без мнения и без референсов — **не дефолти в фиолетовый градиент**,
это самый узнаваемый штамп «сгенерировано ИИ». Дефолт — тёмно-графитовый фон (`#16181d`) + один
спокойный акцент (терракот `#c9704f` или тёмная бирюза `#2f7a78`), плоские заливки, без
градиентов и свечения вообще.

Возьми `assets/stylekit.ts` как шаблон (там уже расписано, какие поля обязательны — их читают
все компоненты банка примитивов) и перезапиши `colors`/`fonts` под то, что выяснил. Не трогай
форму объекта — только значения.

## Шаг 5. Первое видео — спроси, где лежит, предупреди о времени/расходе

Спроси, куда положить исходник (или можно перетащить файл прямо в чат). Перед тем как запускать
тяжёлую обработку — проверь длительность (`ffprobe`) и, если файл длинный (по ощущению — от
30-40 минут), явно предупреди: «файл на N минут, обработка (транскрипция+рендер) займёт примерно
столько-то и заметно потратит дневной лимит — продолжаем или сначала возьмём кусок покороче для
теста?». Не запускай тяжёлый пайплайн молча на файле любого размера.

## Шаг 6. Обработка — по порядку, ничего не пропускать

1. **Транскрипция** через `@remotion/install-whisper-cpp` с `tokenLevelTimestamps: true` и
   флагом `--dtw` — без них не будет word-level тайм-кодов, а они нужны на следующем шаге.
2. **Вырезание пауз** — `scripts/cut_silence.py <video> <words.json> <out.mp4> <out_words.json>
   --audio --level` (флаг `--audio` обязателен — режим по умолчанию в скрипте баговый, режет
   живую речь, см. докстринг скрипта; `--level` сразу прогоняет выравнивание голоса тем же
   заходом). Подробнее, почему именно так — `references/audio-pipeline.md`.
3. **Субтитры** — `/remotion-captions` на пересчитанных словах (`cut_words.json` из шага 2, там
   слова уже примагничены к новому таймлайну — ни одно не потеряется на вырезанных паузах).
4. **Улучшение голоса** — если не сделал флагом `--level` на шаге 2, отдельно
   `scripts/clean_audio.py <video> --render <out>`. Диагностирует и чинит только то, что реально
   сломано (шум/громкость/клиппинг) — не гарантированно «улучшает» звук вслепую, это осознанно.
5. **Обязательный шаг — предложи графику, не жди вопроса.** Прогони расшифровку через словарь
   «маркер речи → примитив» (`references/marker-action-library.md`, реализация примитивов —
   `references/primitive-map.md`, сами компоненты — `assets/primitives/`) и **сформулируй
   конкретно 1-3 места с конкретной графикой** («на 0:14, где ты говоришь про рост в 3 раза —
   предлагаю countUpNumber») — этот шаг нельзя молча пропустить и нельзя заменить общим
   «нужна ли графика?». Дай пользователю решить, какие вставки брать.
6. **Рендер.**

## Правило: новый примитив — всегда предлагай занести в банк

Если по ходу работы (не только на первом видео — в любой сессии) пользователь попросил
что-то, чего нет в `assets/primitives/`, и ты нарисовал компонент с нуля под его конкретный
запрос — **всегда спроси, добавить ли этот компонент в банк примитивов насовсем**, а не только
для этого ролика. Не жди, что пользователь сам догадается попросить — задай вопрос прямо
(«получилось неплохо — сохранить как постоянный примитив в банке, чтобы предлагать его и в
следующих видео?»). Если да — положи файл в `assets/primitives/`, добавь запись в
`references/primitive-map.md` (props, когда уместен) и, если подходит под существующую семью —
в `references/marker-action-library.md`. Банк растёт от реального использования, не только от
того, что заложено при сборке скилла.

## Шаг 7. Превью

- **Claude Desktop (вкладка Code)**: запусти `npx remotion studio`, dev-сервер откроется прямо
  в Browser-панели приложения — ничего дополнительно открывать не надо.
- **Claude Code в терминале**: `npx remotion studio`, дай пользователю открыть выведенный адрес
  в браузере самому.
- **Codex**: своего превью-окна нет — тот же `npx remotion studio`, но адрес нужно открыть в
  обычном браузере пользователя руками, агент это увидеть не может.
