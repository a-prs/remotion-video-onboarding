# Словарь «маркер → действие» для режиссёра Reels (v0.1)

**Задача словаря.** Заменить логику *«арт-директор подбирает ТИП карточки под мысль»* на
*«хореограф ИСПОЛНЯЕТ действие по слову-триггеру, а блоки связаны между собой»*. Цель —
чтобы звук выключил, а по графике было понятно, о чём ролик и в чём мысль. Почти каждый
глагол/ключевое слово должен рождать видимое ДЕЙСТВИЕ с карточкой, а не статичную плашку.

**Как читать.** Слева — маркеры (слова/обороты в речи, как их слышит ASR, с вариациями).
Справа — ДЕЙСТВИЕ (движение) + визуал. Тег готовности:
- `[есть]` — движок уже умеет (компонент/переход существует).
- `[частично]` — есть похожее, но не так, как надо (обычно статично вместо анимации).
- `[новый]` — нужен новый примитив Remotion (это будущий гап-аудит → слой B).

Теги проставлены НАВСКИДКУ и ничего не ограничивают — словарь проектируем как идеал.
Правило связности: **новый блок по возможности ВЫРАСТАЕТ из предыдущего** (стрелка/морф),
а не появляется с чистого листа. Разрозненные плашки — главный враг.

---

## 1. ПОЯВЛЕНИЕ / ВВОД СУЩНОСТИ
Маркеры: *«есть X», «взял X», «подключил X», «Claude / бот / сервер / API / плагин»,
«вот инструмент», «знакомься»*
- Действие: карточка сущности ВЪЕЗЖАЕТ (slide+pop), если есть бренд — впечатывается логотип. `[есть]` (iconTitle/heroCard/chapterCards + brand)
- Если названо несколько подряд («Claude, Codex, Gemini») — они встают стопкой/рядом по одному в такт перечислению. `[есть]` chapterCards/cardPile
- Усиление: у сущности пульсирует ободок, пока о ней говорят. `[новый]` (glow/pulse на активной карточке)

## 2. ОТРИЦАНИЕ / ЗАЧЁРКИВАНИЕ
Маркеры: *«не поможет», «не работает», «не годится», «забудь про X», «это не то»,
«больше не», «мимо», «бесполезно», «уже не»*
- Действие: по произнесению слова — предыдущий текст/карточка **перечёркивается** линией, тускнеет. `[новый]` (strikethrough слова/строки)
- Поверх — **красная плашка-штамп** с отрицанием («НЕ ПОМОЖЕТ») налетает с лёгким наклоном. `[новый]` (red stamp overlay)
- Пример (твоя запись): *«клод-код здесь не поможет»* → лого Claude + текст `Claude Code`, на «не поможет» текст перечёркивается и сверху красное «НЕ ПОМОЖЕТ».

## 3. ЗАМЕНА / ПЕРЕКЛЮЧЕНИЕ / ВМЕСТО
Маркеры: *«вместо этого», «а надо так», «смени», «переключись», «замени», «лучше
сделай», «правильный путь», «вот как надо»*
- Действие: старая карточка уезжает, новая встаёт на её место (transition `replace`/`stack`). `[есть]`
- Сильнее: старая **морфит** в новую (перетекание формы). `[частично]` (morph заявлен, но слабый)
- Тумблер: визуальный переключатель щёлкает из ❌ в ✅. `[новый]` (toggle switch)

## 4. СВЯЗЬ / СТРЕЛКА МЕЖДУ БЛОКАМИ (ядро связности)
Маркеры: *«поэтому», «отсюда», «это ведёт к», «в итоге», «значит», «решает эту
проблему», «и тогда», «из-за этого», «лайфхак, который…»*
- Действие: **из предыдущего блока РАСТЁТ стрелка** в новую карточку (решение/следствие). `[новый]` (inter-card connector, growing)
- Пример (твоя запись): *«лайфхак, который решает эту проблему»* → из блока-проблемы вырастает стрелка в карточку-решение.
- Причинность «потому что»: стрелка назад к причине, подпись на линии. `[новый]`

## 4б. ПРОХОД ЛУПОЙ ПО СВЯЗНОЙ ЦЕПОЧКЕ (алгоритм/пайплайн) — приоритет Андрея
Маркеры: *«алгоритм», «по шагам», «как это устроено», «цепочка», «пайплайн», «сначала…
потом… потом…», «весь путь», «от и до», «как это работает изнутри»*
- Действие: весь процесс нарисован ОДНОЙ непрерывной **связной цепочкой** узлов — линии
  соединены, путь **вьётся змейкой** по экрану (влево-вправо-вниз), он ДЛИННЕЕ экрана.
- По цепочке **едет окошко-лупа** (ограниченная видимая область): держит текущий узел в
  фокусе/увеличении, входящая линия — из предыдущего, исходящая — в следующий. Лупа
  **скользит от узла к узлу в такт речи**. `[новый]` (serpentine connected path + traveling lens/viewport)
- Почему мощно для «звук-офф»: это ОДНА связная линия, и камера физически по ней едет —
  связность неоспорима, глаз видит нить, а не разрозненные плашки. Прямое лекарство от «халтуры».
- Два подрежима: (a) путь зафиксирован, камера/лупа панорамирует по нему; (b) путь нарисован
  целиком, по нему движется подсвечивающая лупа-спотлайт.
- Связка с семьёй №4 (стрелки), №10 (шаги), №16 (аналогия-мост).

## 5. ВЕТВЛЕНИЕ / РАЗДЕЛЕНИЕ
Маркеры: *«разделить», «развести», «два пути», «разветвляется», «отдельно», «каждый
в свой», «разбить на», «по разным»*
- Действие: один узел **расщепляется** на 2-3 ветки (линии расходятся к карточкам). `[новый]` (node split)
- Пример (супергруппа-топики): один чат → веер из N топиков-карточек с иконками. `[частично]` nodeMap статичен
- «Отдельные диалоги»: сетка независимых мини-карточек, каждая своим цветом. `[есть]` cardPile

## 6. ОБЪЕДИНЕНИЕ / СЛИЯНИЕ / КАША
Маркеры: *«свалить в кучу», «смешать», «в одну кучу», «каша», «всё вперемешку»,
«слил воедино», «объединить»*
- Действие: несколько карточек **слетаются в кучу** и наезжают друг на друга (хаотично, с дрожью) — визуал беспорядка. `[новый]` (pile-collapse/tangle)
- Пример («Война и мир вперемешку»): две книги-карточки тасуются через страницу → мешанина. `[новый]`
- Контраст-решение обычно следом через семью №5 (стрелка → «развести»).

## 7. РОСТ / ПАДЕНИЕ / ДИНАМИКА ВО ВРЕМЕНИ (графики — приоритет Андрея)
Маркеры: *«растёт», «выстрелило», «взлетело», «увеличивается», «попёрло», «падает»,
«рушится», «просело», «обвалилось», «жгу деньги», «капает счёт», «пошло вверх/вниз»,
«динамика», «по графику видно»*
- **Гистограмма (bars)**: столбики **анимированно растут** снизу вверх по одному, метка у пика. `[новый]` (animated bar-grow — сейчас bars статичны)
- **Линейный график**: линия **чертится слева-направо**, точка бежит по ней; на росте линия/точка **перекрашивается в ЗЕЛЁНЫЙ**, на падении — в красный. `[новый]` (line-chart draw + point + color-switch)
- «Выстрелило / попёрло»: резкий скачок вверх + вспышка/цвет, sfx surprise. `[новый]`
- «Обвалилось / просело»: точка/столбик **падает** вниз, краснеет, sfx impact. `[новый]`
- «Жгу деньги / капает»: счётчик крутится вверх, монетки утекают. `[новый]` (counter + drip)
- Ключевой смысл: сам ФАКТ движения (вверх/вниз) + цвет (зелёный/красный) должны читаться без звука.

## 8. ЧИСЛА / СЧЁТ / ДЕНЬГИ
Маркеры: *«дважды», «два раза», «30 тем», «48 партий», «50%», «полгода», «X рублей»,
«в N раз», цифры вообще*
- Действие: крупное число **накручивается** (count-up) на heroNumber. `[частично]` heroNumber статичен → нужен count-up
- «Платил дважды»: два одинаковых чека/счёта появляются рядом, знак ×2. `[новый]` (duplicate stamp)
- Доля/процент: donut заполняется по дуге. `[частично]` donut статичен
- Деньги: значок валюты, сумма пульсирует. `[есть]` heroNumber + sfx cash

## 9. СРАВНЕНИЕ / БЫЛО-СТАЛО / ДО-ПОСЛЕ
Маркеры: *«а вот», «зато», «было / стало», «до / после», «раньше / теперь», «лучше /
хуже», «с одной стороны… с другой», «в отличие от»*
- Действие: экран **делится на 2 колонки**, левая (было/минус) серая, правая (стало/плюс) акцентная. `[есть]` twoColumn
- Код «было/стало»: codeCompare две панели. `[есть]`
- Динамика было→стало: левая карточка **перетекает** в правую по стрелке. `[новый]` (before→after morph)

## 10. ПЕРЕЧИСЛЕНИЕ / ШАГИ / ПОРЯДОК
Маркеры: *«во-первых… во-вторых», «сначала… потом», «шаг 1/2/3», «N способов»,
«первое, второе», «по пунктам», «дальше»*
- Действие: **numberedRows** раскрываются по одной строке в такт речи, активная подсвечена. `[частично]` появляются, но без «шаг k из N» подсветки текущего
- Сквозная нумерация: бейдж 01→02→03 не должен обрываться на «ФИНАЛ». `[есть]` (следить в промпте)
- «Дальше/затем»: стрелка ведёт к следующему пункту (связка с №4). `[новый]`

## 11. УСЛОВИЕ / ЛОГИКА
Маркеры: *«если… то», «когда…», «стоит только…», «засада в том, что», «проблема в
том», «но», «однако», «на самом деле»*
- «Если X → то Y»: карточка-условие, стрелка, карточка-исход. `[новый]` (condition branch, связка с №4)
- «Но / на самом деле»: слом — экран дёргается, вводится контр-факт (glitch). `[есть]` sfx glitch, `[частично]` визуальный слом
- «Засада/проблема в том»: подсветка проблемного узла красным. `[новый]` (highlight-warn)

## 12. АКЦЕНТ / РЕВИЛ / СЕКРЕТ
Маркеры: *«оказывается», «вот в чём суть», «секрет в том», «вот почему», «главное»,
«лайфхак», «фишка», «а теперь внимание»*
- Действие: затемнение фона + **спотлайт/зум** на ключевой карточке, остальное гаснет. `[новый]` (spotlight/dim-rest)
- Ключевое слово **выделяется** (accentWord) и увеличивается. `[есть]` accentWord, `[частично]` без масштабирования
- Ревил: карточка переворачивается/раскрывается. `[новый]` (flip reveal)

## 13. ПРОБЛЕМА / БОЛЬ / ХАОС
Маркеры: *«боль», «ад», «кошмар», «путается», «теряется», «абсурд», «бардак»,
«по колено в…», «замучился»*
- Действие: визуал беспорядка — карточки дрожат, съезжают, краснеют, иконки-предупреждения. `[новый]` (chaos/shake)
- Пример («контекст путается, собака стала собакой клиента»): подписи карточек **перепутываются** местами. `[новый]` (label scramble)
- Обычно за болью — семья №4/№12 (стрелка к решению / ревил).

## 14. ВЕРДИКТ / ГАЛОЧКА-КРЕСТ
Маркеры: *«работает», «готово», «получилось», «провал», «не взлетело», «да / нет»,
«верно / неверно», «плюс / минус»*
- Действие: зелёная **галочка**-штамп или красный **крест** налетает на карточку. `[новый]` (verdict stamp ✓/✗)
- Итоговый позитив: cymbal + вспышка (РЕДКО, 1 на ролик). `[есть]` sfx cymbal
- Чек-лист: пункты по одному отмечаются галочками. `[новый]`

## 15. КОД / ТЕРМИНАЛ / ДИАЛОГ С AI
Маркеры: *«команда», «я пишу — он отвечает», «промпт», «в терминале», «код», «запрос»,
«я ему пишу», «бот отвечает»*
- «Я пишу — он отвечает»: **chatBubbles** печатаются по очереди user↔ai. `[есть]`
- Команда/код: **codeAppear**/terminal построчно с подсветкой. `[есть]`
- «Запустил»: терминал печатает, курсор мигает, sfx typing. `[есть]`

## 16. АНАЛОГИЯ / МЕТАФОРА (хук-механика)
Маркеры: *«представь», «это как», «вроде», «как если бы», «знаешь как…»*
- Действие: карточка-образ (таксист / гроссмейстер / сотрудник) вводится, затем **стрелка-перенос** на реальный предмет ролика. `[новый]` (analogy bridge, связка с №4)
- Примеры: лондонский таксист → твой бот со стёртой памятью; Тимур Гореев вслепую → AI-агент, ведущий 30 тем.
- Держать образ визуально, пока разворачивается аналогия, потом «мост» к сути.

## 17. ЦИТАТА / ЧУЖАЯ РЕЧЬ
Маркеры: *«он сказал», «мне пишут», «типичный вопрос», «говорят, что»*
- Действие: **quoteCard** с кавычками, автор снизу. `[есть]`
- Реплика «в лоб»: пузырь-реплика влетает сбоку. `[частично]` chatBubbles

## 18. CTA / ФИНАЛ
Маркеры: *«напиши слово X», «забери базу», «ссылка», «подпишись», «кодовое слово»,
«пиши под видео», «до встречи»*
- Действие: **своя карточка CTA** (не голая плашка) — кодовое слово крупно, стрелка вниз к «комментарии». `[частично]` есть карточка, нет анимации ввода-слова
- «Напиши база»: слово печатается в поле комментария на глазах. `[новый]` (type-in-comment)
- Подписка: кнопка «Подписаться» пульсирует, sfx riser. `[новый]`

## Черновой список НЕДОСТАЮЩИХ примитивов (предварительно, для слоя B)
1. **strikethrough** — зачёркивание слова/строки по таймкоду.
2. **red-stamp overlay** — штамп-плашка поверх (отрицание/вердикт), с наклоном.
3. **inter-card connector** — стрелка/линия, РАСТУЩАЯ между двумя разными карточками (ядро связности).
4. **node split / branch** — узел расщепляется на ветки.
5. **pile-collapse / tangle** — карточки слетаются в «кашу» (хаос).
6. **animated bars / count-up / donut-fill** — рост столбиков, накрутка числа, заливка доли.
6б. **line-chart + color-switch** — линия чертится, точка бежит, зелёный на росте / красный на падении (приоритет Андрея).
6в. **serpentine path + traveling lens** — связная цепочка змейкой + едущее окошко-лупа по узлам (приоритет Андрея; ядро «связности»).
7. **spotlight / dim-rest** — затемнить всё, подсветить одну карточку (ревил).
8. **verdict stamp ✓/✗** — галочка/крест налетают.
9. **flip reveal** — переворот карточки.
10. **glow/pulse на активной карточке** — пока о ней говорят.
11. **label scramble / shake** — перепутать подписи / дрожь (боль-хаос).
12. **before→after morph** — левая карточка перетекает в правую.
13. **toggle switch** — тумблер ❌→✅.
14. **type-in-comment** — слово печатается в поле комментария (CTA).

> Источник примитивов: собственный банк компонентов (см. `assets/primitives/`), перекрашивается
> под стайлкит пользователя (см. `assets/stylekit.ts` и онбординг-шаг про стиль в SKILL.md).

## Открытые вопросы
- Словарь можно расширять новыми глаголами/оборотами по мере использования (семьи 1-18 — не исчерпывающий список, живой).
- Приоритет примитивов на «связность»: кандидаты №3 connector, №2 red-stamp, №1 strikethrough, №7 spotlight — если ролик короткий и нужно выбрать 3-4 из всех, начинай с этих.
- После стабилизации словаря — упаковка в скилл `reels-director` через `skill-creator`.

# ДОПОЛНЕНИЯ ПО ИТОГАМ НЕЗАВИСИМОГО КРИТИКА (v0.2)

## Два системных вывода (важнее отдельных семей)
- **PERSISTENT-SPINE (накопительный скелет).** Все действия v0.1 транзиентны: сыграл — погас.
  Для «звук-офф» финальный кадр должен показывать ВСЮ мысль ролика, а показывать нечего.
  Ввести примитив-скелет: по ходу ролика собирается видимая цепочка `проблема → решение →
  результат`, которая НЕ гаснет. Без него набор красивых жестов ≠ понятный ролик. `[новый]` — приоритет №1.
- **KINETIC-SUBTITLE / ACTIVE-WORD как ДЕФОЛТНЫЙ слой.** Ключевое слово речи ВСЕГДА всплывает
  анимированной подложкой — даже когда ни одна карточка не подошла. Самая дешёвая универсальная
  страховка: каждое предложение получает читаемую графику, а не только «удачные» триггеры. `[новый]` — приоритет №2.
- **Правило хаоса:** любой «беспорядок» (каша/дрожь/scramble) ВСЕГДА в связке с разрешением
  (стрелка→решение) в том же плане. Хаос без разрешения = шум, в муте читается как «просто трясётся».
- **Правило вердикта/штампа:** мишень остаётся на экране, штамп ХОЛД-ится ≥0.8с (иначе текст не прочитать).

## Новые СЕМЬИ (в этой нише — критичные, ниша про боты/автоматизацию)
- **A. ПРОЦЕСС / ПАЙПЛАЙН / ЦИКЛ** *(«на вход — на выход», «прогоняю через», «пайплайн»,
  «конвейер», «автоматом», «в фоне крутится», «по кругу», «цикл», «само работает», «24/7»,
  «по расписанию», «дёргает», «триггерится»)* → конвейер/шестерёнки/петля: объект въезжает

## Device-style мини-инфографика (2026-08-12, из референс-рилса; границы проработаны Opus)
Техно-карточки в стиле CLI/конфига. Реализация → `primitive-map.md`. Все пять — T3/T2 **fullscreen**,
самоподложечные, крупные. Между двумя fullscreen держи overlay-бит с лицом. Главный конкурент этих пяти —
друг друга и старые «списочные» примитивы (numberedRows/checklist/spotlight/funnel), поэтому границы ниже — обязательны.

- **СТРУКТУРА / ДЕРЕВО ФС** *(«структура папки/репо/навыка», «как устроен скилл изнутри», «из чего состоит
  проект», «где лежит файл», «run.sh лежит тут», «конфиг в корне», «рабочая директория», «дерево каталогов»)*
  → отступ-гайды (├─ └─ │) раскрываются сверху вниз, ОДИН узел бирюзовый + бейдж-таргет (▶ run.sh). `fileTree`.
  *(≠ `numberedRows`: есть вложенность файлов, а не плоское «во-первых»; ≠ `workspaceScene`: нет прогона
  терминала, только структура; ≠ `spineFlow`/`nodeSplit`: ФС-иерархия, не логические связи; ≠ `rowCycler`:
  одно дерево, а не альтернативы-варианты.)*
- **МАСКА / GLOB-ФИЛЬТР** *(«по маске», «по паттерну путей», «`*.tsx`», «все `.md`», «по расширению»,
  «цепляет только `.json`», «подходят под шаблон», «матчатся вот эти», «auto-load совпавших», «glob/grep по путям»)*
  → сверху маска-заголовок, файлы списком; совпавшие загораются бирюзой + ✓ + тег, несовпавшие тусклые. `globMatch`.
  *(≠ `gatePass`: разбор по РАСШИРЕНИЮ/имени файла, а не по allow-list ДЕЙСТВИЙ — см. флаг ниже; ≠ `checklist`:
  причина подсветки — паттерн, а не человеческий критерий; ≠ `fileTree`: плоский список, не дерево.)*
  ⚠️ Берём `globMatch` ТОЛЬКО когда маска/расширение названы или очевидны — иначе в муте не видно ПОЧЕМУ
  подсветилось (нет видимой причины) → тогда `rowCycler`/`checklist`.
- **ЛИМИТ / ПОТОЛОК / CAP** *(«лимит», «потолок», «квота», «cap», «упёрся в предел», «больше не влезает»,
  «контекстное окно забито», «обрезается», «лишнее выкидывается/теряется», «бюджет токенов/символов»,
  «200к токенов и всё», «переполнение»)* → бар доливается к КРАСНОЙ вертикальной черте, хвост за лимитом
  КРАСНЕЕТ + штамп «dropped», сверху счётчик до value. `limitBar`. *(≠ `progressBar`: тут ПОТЕРЯ за краем, а не
  нейтральная готовность к 100%; ≠ `countUp`/`odometer`: есть потолок, не просто число; ≠ `donutFill`: про
  переполнение, а не долю; ≠ `barsGrow`: один бар против линии, не сравнение категорий.)*
- **ГЕЙТ / ALLOW-LIST** *(«allow-list», «whitelist», «вайтлист», «белый список», «проходят автоматом»,
  «разрешено без спроса», «не спрашивает разрешения», «пускаем сразу», «разрешённые тулзы/команды»,
  «проходят гейт/фильтр», «прошли модерацию», «апрувнуто автоматом»)* → чипы едут слева-направо сквозь
  вертикальный барьер по очереди, на той стороне зеленеют с ✓. `gatePass`. *(≠ `funnel`: тут ПРОПУСК-разрешение,
  а не сокращение N→K/отсев; ≠ `pipeline`: один гейт, не конвейер этапов; ≠ `checklist`: allow-list, а не критерии
  по галочке; ≠ `verdict`: очередь чипов, а не один ✓/✗; ≠ `globMatch`: разрешение ДЕЙСТВИЙ, не маска файлов.)*
- **ПЕРЕБОР / ОДНО ИЗ N** *(«одно из трёх», «любой из них», «перебираю варианты», «может лежать в трёх местах»,
  «может быть здесь, здесь или здесь», «три режима/тира/уровня», «на выбор», «среды: dev/stage/prod»,
  «personal/project/plugin», «то одно, то другое»)* → бирюзовая подсветка БЕЖИТ ПО СТРОКАМ ПО КРУГУ, активная
  горит, прочие тусклые. `rowCycler`. *(≠ `numberedRows`: взаимоисключающие альтернативы БЕЗ порядка, не
  «во-первых/шаг 1-2-3»; ≠ `spotlight`: перебор по кругу, а не один финальный фокус/суть; ≠ `checklist`: «одно ИЗ N»,
  а не «все выполнены»; ≠ `fileTree`: варианты размещения, не вложенная структура.)*
  ⚠️ Слабейший из пяти по «звук-офф» (бегущая подсветка ≈ `numberedRows`/`spotlight`). Ставить ТОЛЬКО на
  взаимоисключающие опции (тиры/режимы/места), окно ≥ ~2.5с и `holdSec` подольше (иначе цикл не читается).

**🔑 Ключевое пересечение — `globMatch` ↔ `gatePass`** (оба про «автоматом проходит/подхватывает»): различитель
ЕДИНСТВЕННЫЙ — **дискриминатор по РАСШИРЕНИЮ/паттерну ФАЙЛА → `globMatch`; именованный allow-list ДЕЙСТВИЙ/

  ручные критерии по галочке; ≠ `verdict`: построчный статус многих пунктов, не один ✓/✕ на сущность; ≠ `globMatch`:
  причина — прошло ПРОВЕРКУ, а не совпало с маской файла.)* ⚠️ скан-линия должна быть ВЫРАЖЕННОЙ, иначе съедет в `checklist`.
- **КОД-РЕВЬЮ / ДИФФ** *(«код-ревью / ревью кода», «смотрю дифф / git diff», «что изменилось», «это добавили — это
  убрали/выпилили», «внёс правки», «плюс строки, минус строки», «PR review»)* → строки инлайн-диффа проявляются
  сверху-вниз: ДОБАВЛЕННЫЕ бирюзовые с «+», УДАЛЁННЫЕ красные с «−», контекст тусклый. `diffReview`. *(≠ `codeCompare`:
  унифицированный дифф в ОДНУ колонку, не две панели файл↔файл; ≠ `strikeNegate`: построчные изменения кода, не
  зачёркивание одной идеи; ≠ `auditScan`: показывает ИЗМЕНЕНИЯ +/−, а не результат проверки ✓/✕.)*
- **СВЕРКА ДВУХ СТОРОН** *(«сверяю / сверка», «сопоставляю», «бьётся / не бьётся», «сходится / не сходится», «сверяю с
  эталоном», «свожу дебет с кредитом», «сверяю чек с выпиской», «нашёл расхождение»)* → две колонки строк, для КАЖДОЙ
  совпавшей пары коннектор слева-направо (зелёный), НЕсовпадение оранжевое с разорванной связью + ✕. `reconcileMatch`.
  *(≠ `beforeAfter`: параллельная сверка двух наборов, не превращение было→стало; ≠ `equals`: много пар с match/mismatch,
  не одна эквивалентность «то есть»; ≠ `plugConnect`: коннектор = «совпало», не физическое подключение систем;
  ≠ `nodeSplit`: колонки СХОДЯТСЯ парами, а не узел расходится на ветки.)* Ниша финансовая/сверочная — реже остальных четырёх.
- **СОРТИРОВКА ПО КОРЗИНАМ / ТРИАЖ** *(«сортирую / раскидываю по», «разбираю очередь», «триаж», «по категориям / по
  типам», «раскладываю по папкам/полочкам», «распределяю / классифицирую», «маршрутизирую тикеты», «кого куда»,
  «разгребаю входящие»)* → очередь чипов сверху РАЗЛЕТАЕТСЯ по цветным корзинам-категориям снизу. `sortBins`. *(≠ `kanban`:
  анимированный разлёт-процесс, не статичные колонки-статусы; ≠ `funnel`: распределение по РАЗНЫМ категориям без отсева,
  не сокращение N→K; ≠ `rowCycler`: множество элементов летит по корзинам, а не перебор одной опции из N.)*
- **РАНЖИРОВАНИЕ / ПРИОРИТИЗАЦИЯ** *(«ранжирую / приоритизирую», «расставляю приоритеты», «что делать первым / что
  сначала», «что важнее», «сортирую по важности», «топ приоритетов», «главное наверх», «по убыванию», «выше — важнее»)*
  → горизонтальные бары дорастают до value, затем ПЕРЕСОРТИРОВЫВАЮТСЯ (съезжают по вертикали) в ранг, верхний =
  наибольший и подсвечивается. `rankBars`. *(≠ `barsGrow`: ключевое — РЕОРДЕР по приоритету, не статичное сравнение
  категорий; ≠ `numberedRows`: порядок ВЫЧИСЛЯЕТСЯ из величин, не задан «во-первых»; ≠ `spotlight`: сортирует весь
  список, не выделяет одну суть.)* ⚠️ самый рискованный: реордер должен быть ЗАМЕТНЫМ + окно ≥ ~3с, иначе → `barsGrow`.

**🔑 Опасная пара №1 — `auditScan` ↔ `diffReview`** (оба «агент прошёлся по коду»): различитель — **статусы ✓/✕ по
строкам (прошло/провалилось проверку) → `auditScan`; изменения +/− (что добавили/убрали) → `diffReview`**. Мнемоника:
«ищет ошибки → auditScan; показывает правки → diffReview».
**🔑 Опасная пара №2 — `sortBins` ↔ `rankBars`** (оба «сортирую»): **по КАТЕГОРИЯМ (несколько корзин) → `sortBins`; в
ПОРЯДОК по метрике (один ряд, ранг) → `rankBars`**. Мнемоника: «по типам → корзины; по важности → ряд».

## Звуки (SFX) — маркер → категория (источник правды: `agents/montage-vertical/sfx/registry.json`)
Поле `sfx` на акте, ~3-6 на ролик 60с (на усиление, не на каждый бит). Полный список категорий — в промпте
(`plan_prompt.md`, секция SFX). Ниже — только добавленные 2026-08-15 (донор @dosvidaria_x, «небанальные звуки»):
- **`abacus`** *(«считаю / подсчёт / перебор чисел / тэлли / сколько всего»)* → тактильные клики деревянных счётов.
  Пара к `countUp`/`checklist`/`numberedRows`. ≠ одиночная цифра-акцент (там `pop` или ничего).
- **`flying`** *(«взлетает / запускаю / улетело / полетели / буст»)* → игровой whoosh снизу-вверх, вход элемента.
  ≠ `whoosh` (нейтральный горизонтальный переход между актами).
- **`atmosphere`** *(спокойное вступление / хук-настроение / мягкий ревил)* → тянущийся эмбиент-бэд, тихий (gain 0.08).
  ⚠️ ОДИН раз на ролик под интро/спокойный ревил — это подложка-настроение, НЕ удар на бит.
- **`glitter`** *(«красота / вау / преображение / засиял / магия»)* → искры-блёстки, 2 варианта ротируются
  (`shui_glitter` шиммер + `kirarin_glitter_star` звёздный твинкл). Пара к позитивному `verdict`/`beforeAfter`-after.
  ≠ `surprise` (там неожиданность-поворот, а тут восхищение-красота).
