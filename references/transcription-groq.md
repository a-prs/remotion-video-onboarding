# Groq-транскрипция — альтернатива локальному whisper.cpp

## Зачем

Локальный `@remotion/install-whisper-cpp` (модель `medium`, ~1.5 ГБ) — дефолт скилла осознанно:
офлайн, без ключа, без стоимости за прогон. Но на CPU это медленно, и точность на русской речи у
`medium` заметно ниже, чем у `large-v3`. Groq хостит `whisper-large-v3` на своём железе — быстрее и
точнее, но требует `$GROQ_API_KEY`, стоит денег за прогон (кредиты Groq) и отправляет аудио проекта
в их облако. Поэтому это **выбор пользователя**, персистентный флаг `transcription-engine:` в шапке
`assets/stylekit.ts` (см. SKILL.md Шаг 6 п.1) — не дефолт, спрашивается один раз на проект.

## Как это устроено — `scripts/transcribe_groq.py`

Без сторонних Python-зависимостей (никакого `requests`/`httpx`) — multipart-запрос собран руками
через stdlib `urllib.request`, чтобы не тянуть новый pip-пакет поверх уже нужных `numpy`/`scipy`
(та же логика, что у остального аудио-пайплайна — `audio-pipeline.md`).

1. Вытаскивает аудио из видео в mono 16kHz mp3 @64kbps (`ffmpeg`) — этого достаточно для ASR и
   держит файл маленьким.
2. Если файл длинный, режет на куски (`plan_chunks()`) — у Groq есть потолок на размер одного
   файла на загрузку. Целевая длина куска — `--chunk-minutes` (дефолт 12 мин), но реальная точка
   разреза подтягивается к ближайшей настоящей паузе в пределах 20с от цели (переиспользует
   `detect_silences()`/`probe_duration()` из `cut_silence.py` — та же логика, что и для
   snap-границ дублей, см. `audio-pipeline.md`), чтобы разрез куска не пришёлся ровно на середину
   слова. Короткое видео (в пределах ~1.15× целевой длины) уходит одним куском без разбиения.
3. Каждый кусок шлётся на `https://api.groq.com/openai/v1/audio/transcriptions`
   (`model=whisper-large-v3` дефолт, можно `whisper-large-v3-turbo` — быстрее/дешевле, чуть менее
   точная; `response_format=verbose_json`, `timestamp_granularities[]=word` — без этого не будет
   word-level тайм-кодов, а они нужны на следующих шагах пайплайна).
4. Тайм-коды слов каждого куска сдвигаются на смещение куска (`+= chunk_start`) и склеиваются в
   единый список — результат в ТОМ ЖЕ формате `{"words": [{word,start,end,confidence}]}`, что и у
   локального whisper.cpp, дальше пайплайн (поиск дублей, вырезание пауз, субтитры) не отличается.

## Ошибки — что показывает скрипт

- `$GROQ_API_KEY` не задан — понятное сообщение в stderr, выход с кодом 1, ключ никогда не
  печатается.
- HTTP 401 — «ключ отклонён», проверить `$GROQ_API_KEY`.
- HTTP 413 — кусок всё ещё слишком большой, уменьшить `--chunk-minutes`.
- Пустой `words` в ответе (200 OK, но без слов) — печатает предупреждение и обрезанный сырой ответ
  в stderr, не падает молча с пустым результатом.

## Статус

Реализовано и покрыто офлайн-тестами (юнит-тест на разбиение по паузам синтетическим аудио + сквозной
прогон с замоканным `call_groq()`, проверена математика смещений и совместимость формата с
`load_words()`) — **живого вызова к реальному Groq API ещё не было** (в сессии реализации не было ни
сети, ни ключа Андрея). Контракт запроса (`timestamp_granularities[]` как повторяемое multipart-поле,
структура ответа `verbose_json`) собран по документации Groq/OpenAI-совместимого API на момент
реализации (2026-08-28) — если Groq вернёт что-то другое при первом реальном прогоне, ошибка будет
видна явно в stderr (см. выше), не тихим пустым результатом.
